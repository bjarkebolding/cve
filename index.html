      Method How this is measured

      Methodology

      Public data only, rebuilt daily. Origins say what kind of software a CVE is; AI relations say how it involves AI; exploitation comes from CISA KEV and Project Zero.

      Show definitions, accuracy and caveats

      Origins (Part 1)

      Every published CVE gets exactly one origin — what kind of software it is, regardless of AI. Rules are checked in this order, except that CMS plugins are checked before open-source packages, so a WordPress plugin with a package URL counts as a plugin:

        CISA KEV: what it measures

        "Exploited" on this page means listed in CISA's Known Exploited Vulnerabilities (KEV) catalogue. KEV is a lower bound, not a census: CISA lists a CVE only with reliable evidence of exploitation and an available fix or mitigation, and it focuses on products US federal agencies run. A KEV date is when CISA listed the CVE, not when exploitation began; attacks often start earlier. KEV additions in a year include older CVEs newly listed, so they measure CISA's intake, not the volume of attacks. Commercial catalogues (for example VulnCheck KEV) list more CVEs, often earlier.

        Zero-day proxy

        "KEV-listed at disclosure" = a CISA KEV entry added at most one day after its CVE was published. It undercounts true zero-days (exploitation CISA confirms later is missed and never fills in), rises when CISA lists faster (as in 2026, when its deadlines tightened), and is bucketed by CVE publication year; KEV additions are bucketed by date added. Google Project Zero's in-the-wild tracker is shown alongside as an independent count.

        A CVE is AI-related when at least one of these relations applies, other than "found by AI": an AI tool finding a bug in ordinary software (curl, OpenSSL) is a discovery trend, counted across all CVEs, not AI attack surface.             Gartner's four critical threats

            The "Threats" section is organised around the four critical threats for 2026–2027 named in Gartner's press release "Gartner Identifies Four Critical Threats Requiring Urgent Improvements from Cybersecurity Leaders" (2 June 2026): AI application compromise, deepfake identity impersonation, software supply chain and prompt injection. Mapping: AI application compromise = CISA KEV entries for CVEs with the agent, AI-software or AI-feature relation; software supply chain = the open-source share of KEV additions (open-source CVE and malicious-package counts are context, both distorted by filing and bulk reports); prompt injection = CVEs with the AI-specific-weakness relation, of which none is in KEV; deepfakes have no CVE signal. The signal ratings are this dashboard's own judgement of what public vulnerability data can see, not Gartner's ThreatScape placement. Gartner has not reviewed or endorsed this dashboard.             How accurate is the matching

            Severity

            One CVSS family per CVE, from the CVE record: the CNA's CVSS v3.1, else CNA v4.0, else CNA v3.0, else CISA-ADP (Vulnrichment) v3.1. Part 1's severity uses only the record; Part 2's tables fall back to NVD's score (v3.1 → v4.0 → v3.0, never v2) when the record has none.

            Caveats

            • The AI tagging is a rule-based heuristic over descriptions, products, credits and CWEs: expect misses and some false matches (see the measured precision and recall).
            • "Found by AI tools or AI labs" relies on the CVE record's credits. Most records credit people, not tools, so this undercounts AI-assisted discovery; it also counts researchers who work at an AI lab.
            • "AI compute" includes NVIDIA's consumer GPU drivers: NVIDIA ships one driver branch for GeForce and data-center GPUs.
            • Counts reflect the CNA mix — new or very active assigners (VulnCheck, huntr, GitHub) change the curve independently of the underlying software.
            • CISA KEV is a lower bound of exploitation: it lists only exploitation CISA has confirmed and judged actionable, and it favours products US agencies run (Microsoft, Cisco, Fortinet…).
            • "Open-source projects & packages" includes every GitHub-assigned (GitHub_M) record. GitHub's CNA issued far more CVEs in 2026 than in 2025, so part of that origin's growth is a reporting change, not only more vulnerable code.
            • EPSS is a model estimate, not an observation; it is shown to prioritise, not to prove exploitation.
